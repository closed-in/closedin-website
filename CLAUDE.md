# closedin.io website, werkafspraken voor Claude Code

Lees eerst `CONTRIBUTING.md` en daarna `research/REFERENCE-NOTES.md` (ontwerpkeuzes en valkuilen per ronde).

- **Live = branch `main`.** Beveiligd: alleen via pull request, mergen doet Max. Werk nooit op `main`.
- **Nieuwe site = branch `redesign-2026-10`.** Begin elke sessie met `git pull`, eindig met commit en `git push`. Elke push geeft een preview-link in de pull request.
- **Voor elke push twee checks:** `python3 scripts/check-trackers.py` (eindigt op ALL PASS; dekt alle pagina's behalve pipeline-demo) en `python3 scripts/check-copy.py` (PASS). Faalt er een, dan niet pushen. Na wijzigingen aan links of pagina's ook `node scripts/check-links.mjs --internal` (links: PASS; zonder `--internal` ook de externe links).
- **Nooit aanraken:** de tracker-blokken in de head (Vercel Analytics, GA4, Prospect Pro, Stairoids, LinkedIn, Meta), de cookiebanner (Claydar), Leadboxer en het JSON-LD blok. Die blijven byte-identiek aan `main`.
- **Nooit:** `git push --force`, `git reset --hard`, `git clean`, `.env` of API keys committen. Secrets staan in Vercel.
- **Copy:** Engels, geen em dash, geen emoji, nooit "open rate", merknaam altijd `closed:in`.
- **Lokaal draaien:** `cd scripts && npm install && npx serve -l 8080 ../case-study-showcase`, dan http://localhost:8080. Screenshots en audits: `node scripts/audit.mjs`.
- **Pagina's (sinds de nachtaudit van 20-10 alle 37 in één ontwerp).** Alles draait op `assets/css/site.css` (nav, footer, knoppen, sluier, lightbox) plus een paginablad: de homepage op `home.css`; Cases, Resources en Team op `pages.css` (met `pages.js`); de acht casepagina's op `pages.css` en `case.css`; de zes landingspagina's en pricing daarbovenop ook `landing.css`; de Resources-menu-pagina's, de gated resources, de blogartikelen en privacy op `docs.css` (hun oude inhoudsopmaak, door docs.css in het nieuwe ontwerp getekend). Omgezet met eenmalige generators in `scripts/` (`build-inner-pages.py`, `build-docs-pages.py`, `build-docs-pages-2.py`, `build-case-pages.py`, `build-landing-pages.py`, `build-404.py`) die de oude pagina's uit git lezen: draai ze niet opnieuw over later handwerk heen. Overzichtspagina's (Cases, Resources, Blog) openen donker, detailpagina's licht (`phero--light`, `hero--light`). Nav, footer, sprite en sluier zijn kopieën van `index.html` (op de pagina's in submappen met absolute links): wijzig je er een, pas hem op alle pagina's aan. Alleen `pipeline-demo.html` staat bewust nog in de oude stijl. De paginatransitie (sluier) draait in `assets/js/veil.js`, dat in de head vóór GSAP staat zodat de opening meteen start.
- **Linkpreviews:** elke pagina heeft een eigen beeld in `assets/img/og/` (`node scripts/og-images.mjs` met de lokale server aan, daarna `python3 scripts/set-og.py`). Nieuwe kop of cijfers: beeld opnieuw maken en de naam een nieuwe versie geven (`-v2`), vanwege de cache van zeven dagen.
- **Afbeeldingen** onder `/assets/img/` worden zeven dagen gecachet: nieuwe versie is een nieuwe bestandsnaam.
- **Werkverdeling:** werk je tegelijk met iemand anders aan hetzelfde bestand, maak dan een eigen branch vanaf `redesign-2026-10` en open een pull request naar die branch.
